The Problem:

The service account you are using to deploy from your local machine or through GitHub Actions does not have the permission to enable the Artifact Registry API (artifactregistry.googleapis.com) in your Google Cloud project. Modern Firebase deployments, especially those with Cloud Functions, require this API to store and manage the code for your functions.

The error message is telling you that the "caller" (your service account) needs the Service Usage Consumer role to proceed.

How to Fix It:

You need to add the required IAM role to your service account in the Google Cloud Console.

Navigate to the IAM Page: Open the IAM & Admin page for your project by using this link (replace *** with your actual project ID from the error message): https://console.developers.google.com/iam-admin/iam?project=***

Find Your Service Account: Locate the service account you're using for deployments.

If you're deploying from GitHub Actions, it's the service account associated with the FIREBASE_SERVICE_ACCOUNT_SIGNETAI secret. The name usually looks like firebase-adminsdk-... or github-actions@....
If you're deploying from your local terminal and are logged in with your personal Google account, you need to grant this role to your own email address. However, the best practice is to use a dedicated service account.
Edit Permissions: Click the pencil icon (Edit principal) next to the service account.

Add the Role:

Click + ADD ANOTHER ROLE.
In the "Select a role" filter, type Service Usage Consumer and select it from the list.
Click SAVE.
Important Recommendation:

For modern Firebase deployments that include Cloud Functions, you will likely need additional permissions to avoid future errors. I strongly recommend adding these two roles as well while you are on the IAM page:

Cloud Functions Admin: To manage function deployments.
Cloud Build Editor: To allow the service to build your functions.
